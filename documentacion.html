1. ¿Qué es Angular?

Angular es un framework de desarrollo frontend creado y mantenido por Google. Permite construir aplicaciones web de una sola página (SPA — Single Page Application) usando TypeScript como lenguaje principal.

A diferencia de una página web tradicional donde cada click carga una nueva página desde el servidor, en Angular toda la navegación ocurre en el navegador: el servidor entrega el código una sola vez y Angular se encarga de mostrar u ocultar secciones según la ruta activa.

¿Por qué TypeScript?

TypeScript es un superconjunto de JavaScript que agrega tipado estático. Esto significa que se declara el tipo de cada variable, parámetro y retorno de función. El compilador detecta errores antes de ejecutar el código, haciendo el desarrollo más seguro y predecible.

Angular 17+ — Componentes standalone

Desde la versión 17, Angular promueve los componentes standalone: cada componente declara sus propias dependencias en el array imports, sin necesidad de módulos (NgModule). Este proyecto usa ese enfoque moderno.

2. Conceptos fundamentales utilizados

🧱 Componentes

Un componente es la unidad básica de Angular. Cada componente tiene tres archivos: .ts (lógica), .html (vista) y .scss (estilos). Se declara con el decorador @Component.

@Component({
  selector: 'app-product-card',
  imports: [CurrencyPipe],
  templateUrl: './product-card.html',
})
export class ProductCard { ... }

El selector es la etiqueta HTML con la que se usa el componente: <app-product-card>.

📐 Interfaces

Las interfaces son contratos de TypeScript que definen la forma de los datos. No generan código en runtime — son solo anotaciones que el compilador usa para detectar errores. Si se accede a una propiedad que no existe en la interfaz, TypeScript avisa antes de ejecutar.

export interface Product {
  id: number;
  title: string;
  price: number;
  category: string;
  thumbnail: string;
  stock: number;
  rating: number;
}

⚙️ Servicios e inyección de dependencias

Un servicio es una clase con lógica reutilizable (llamadas HTTP, estado compartido). Con providedIn: 'root', Angular crea una única instancia del servicio para toda la aplicación. Los componentes lo reciben mediante inject() — Angular resuelve la dependencia automáticamente.

@Injectable({ providedIn: 'root' })
export class CartService {
  // Una sola instancia compartida en toda la app
}

// En el componente:
cartService = inject(CartService);

🔀 Control de flujo — @if y @for

Angular 17+ introduce sintaxis de control de flujo directamente en los templates, sin necesidad de importar directivas.


@if (product.stock === 0) {
  <span>Sin stock</span>
} @else {
  <button>Agregar</button>
}


@for (product of products; track product.id) {
  <app-product-card [product]="product" />
}

El track product.id le dice a Angular cómo identificar cada elemento para actualizar solo lo que cambió en el DOM.

📡 @Input y @Output

@Input permite que un componente padre le pase datos a un componente hijo.
@Output permite que el hijo notifique al padre de un evento.

// Hijo (ProductCard)
@Input() product!: Product;
@Output() addToCart = new EventEmitter<Product>();

// Padre (template)
<app-product-card
  [product]="item"
  (addToCart)="onAddToCart($event)">
</app-product-card>

Los corchetes [ ] indican binding de entrada (dato va hacia el hijo). Los paréntesis ( ) indican binding de evento (dato sube al padre).

🔔 Signals

Los signals son valores reactivos introducidos en Angular 17. Cuando un signal cambia, todo lo que depende de él en el template se actualiza automáticamente, sin necesidad de detectar cambios manualmente.

// Declarar un signal
items = signal<CartItem[]>([]);

// Computed: se recalcula cuando items cambia
total = computed(() =>
  this.items().reduce((sum, i) => sum + i.product.price * i.quantity, 0)
);

// Leer el valor: items() con paréntesis
// Escribir: items.set([]) o items.update(fn)

5. Servicios

CartService

Mantiene el estado global del carrito. Al ser providedIn: 'root', existe una única instancia compartida entre ProductsPage, Cart y CheckoutPage. Todos leen y escriben el mismo carrito.

6. Ruteo

El ruteo de Angular permite navegar entre páginas sin recargar el navegador. Se configura en app.routes.ts y se activa con provideRouter(routes) en app.config.ts.

export const routes: Routes = [
  { path: '', redirectTo: 'productos', pathMatch: 'full' },
  { path: 'productos',  component: ProductsPage  },
  { path: 'checkout',   component: CheckoutPage  },
  { path: 'nosotros',   component: AboutPage    },
];
RutaComponenteDescripción
/—Redirige automáticamente a /productos
/productosProductsPageCatálogo con filtro y carrito lateral
/checkoutCheckoutPageFormulario de compra y resumen
/nosotrosAboutPageInformación sobre la tienda

En el navbar se usan routerLink y routerLinkActive: el primero define a dónde navegar al hacer click; el segundo agrega la clase CSS active al link de la ruta activa automáticamente.

8. APIs externas

DummyJSON — catálogo de productos

URL: https://dummyjson.com/products

API pública y gratuita que provee datos de productos de electrónica. No requiere registro ni clave de API.

Endpoint usadoQué devuelve
GET /products/category/smartphonesLista de smartphones con id, title, price, thumbnail, stock, rating
GET /products/category/laptopsLista de laptops
GET /products/category/tabletsLista de tablets
GET /products/category/mobile-accessoriesLista de accesorios

La respuesta tiene la forma { products: [...], total: N }. El operador map() de RxJS extrae el array antes de entregárselo al componente.

MockAPI — órdenes de compra

URL: https://6a42d25a7602860e6521e3e7.mockapi.io/orders

Servicio que simula una API REST con persistencia real. Permite crear, leer y eliminar órdenes de compra.

OperaciónMétodoCuándo se llama
Obtener órdenesGETDisponible en OrderService
Crear ordenPOSTAl confirmar el formulario de checkout
Eliminar ordenDELETEDisponible en OrderService

9. Formularios reactivos (Reactive Forms)

Los Reactive Forms definen la estructura y validaciones del formulario directamente en el TypeScript, no en el HTML. Esto los hace más fáciles de testear y mantener.

// Definición del formulario en checkout-page.ts
form = this.fb.group({
  customerName: ['', [Validators.required, Validators.minLength(3)]],
  email:        ['', [Validators.required, Validators.email]],
  address:      ['',  Validators.required],
  phone:        ['', [Validators.required, Validators.pattern(/^\d{8,15}$/)]],
});
CampoValidaciones
customerNameRequerido, mínimo 3 caracteres
emailRequerido, formato de email válido
addressRequerido
phoneRequerido, solo dígitos, entre 8 y 15 caracteres

Los mensajes de error se muestran solo si el campo fue tocado (touched) y tiene errores, evitando mostrar errores antes de que el usuario interactúe:

@if (form.get('email')?.invalid && form.get('email')?.touched) {
  <small class="text-danger">Ingresá un email válido.</small>
}

Si el usuario hace click en "Confirmar" sin completar el formulario, markAllAsTouched() fuerza que todos los campos muestren sus errores de una vez.
